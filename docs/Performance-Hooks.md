# MMIO 钩子、地址分发与转换链

性能基线使用 **0.37.0 最后一个不含异步框架的提交** `cec42e1f3a25bd8804129ff4c349a0dd54128742`。候选是在该提交上应用同一核心优化，两个测量版本均无异步 admission。PR 集成目标是当前 main `fb37d681df861643aa0150459bd73c37f4d594dd`（0.38.0），保留其 admission；本页不把 0.38 与 0.37 的版本差额算作优化收益。

2026-11-12 同机测量。这里是直接 RegisterMap 软件访问，未运行真实 QEMU dispatch，也不是硬件 MMIO 延迟。手写对照按 `pre_access → if/else 范围解码 → 1000-case switch → 存储/回调` 建模；范围数量与业务复杂度是合成负载，不声称复现某台设备的原代码。

## 为什么同一流程仍有差距

手写路径的范围、寄存器位置和转换表达式能直接出现在同一个编译单元，编译器可以内联、常量传播并优化 switch。框架则需要执行运行时 View 选择、共享 Hash 查找、上下文准备和动态调用。相同的流程框图不代表相同的机器指令和数据依赖。

源码中有两个独立问题：

- **钩子会改变执行路径。** 0.37 的读写入口有 `if (plan && !pre_access_)`，全局钩子会跳过 scalar / mapped scalar；普通 View 钩子也排除标量资格。即使钩子只计数，仍需走更重的 resolve / prepare 流程。这部分可以避免。
- **动态转换需要额外处理。** `mapped_scalar()` 中 identity resolver 需读取当前绑定、保护 callable 生命周期、检查结果；重定向在当前后端还要解析目标 View。index resolver 的 `AccessResolverSlot::from_frame()` 同样保留本次 callable，准备调用帧与索引上下文，检查范围并计算存储位置。多线程进程中的 shared_ptr 保留/释放可涉及原子操作；这些保护支持回调自换绑/清除，不能直接删除。此处没有逐次 MMIO 堆分配，也不能将测到的全部差距都归因于引用计数或一次间接调用。

## 改动

1. 允许全局 / View 钩子复用已支持钩子与存储重读的 mapped scalar 执行器，取消全局钩子导致的强制通用回退。
2. 钩子复用已有 `EventCallback` full/frame 适配，两个入口共享同一可变闭包。轻量 frame 在调用者编译单元准备 info，使编译器能删除钩子不使用的字段；完整字段、按值复制、空/null 函数原有失败行为保持。
3. 固定的标量资格与路径权限交集在 `finish()` 写入每挂载 prepared context，`fast_access()` 从约 80 行缩为约 40 行，减少重复元数据检查。仍使用原有 View / Hash 后端，不缓存 resolver 返回值。

保持全局 → 目标父 View → 子 View 的钩子顺序、换绑/清除生命周期、异常行为、存储重读、RO/权限拒绝不执行钩子、宽事务每拍语义、动态日志和快照。头文件与库必须配套重编译。0.38 中配置 deferred_writes 的端点继续经过 admission 通用路径，本页不代表这种配置的收益。

## 测量方法

Linux x86_64 / Intel Xeon Platinum 8573C 虚拟机，GCC 14.2，C++20、`-O3 -DNDEBUG -fno-strict-aliasing`，无 LTO。固定 CPU 0，线程 CPU 时间；每进程先启动并退出一个线程，确认 glibc 单线程标志为 0，MMIO 本身串行。测量期间不同时编译。

两个版本使用同一份本补丁的 `benchmarks/mmio.cpp`，各自配套头文件与库。每场景 100,000 个地址、8 轮，去掉第一轮，再取 7 轮中位数；3 轮交替版本进程对再取中位数。96 场景矩阵每轮 2 passes，24 场景转换拆分每轮 3 passes。场景顺序按固定种子打散，四个引擎的轮次顺序轮换。所有版本对 checksum 一致。

四个引擎是 regfw、简单解码的 switch_raw / switch_normalized，以及 if/else 范围链加 switch 的 range_switch。本页手写列使用 **range_switch**。三个手写引擎均在解码之前执行可观察的 hook 计数；框架保留解析成功后的钩子语义。只测有效请求，正确性对照含 1/2/4 字节访问、存储、读响应、回调及钩子次数，不证明非法请求的钩子时序等价。

钩子不读取 info，只计数，衡量低业务工作量下的框架成本。真实钩子若读取/复制完整 info 或做复杂工作，应重新测量。寄存器回调同样执行一致的可观察工作。手写 hook 是固定函数，框架保留动态绑定能力。INFO logger 场景只用于框架版本间比较，手写参照没有框架诊断日志。
