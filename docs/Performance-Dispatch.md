# MMIO 分发查表与三倍差距定位

本轮基线为 PR 首两次改动 `39128af` 的同步回移版，候选为增加本页改动的同步版；两者都建立在无异步的 0.37 提交 `cec42e1` 上，使用同一份基准源码、头文件和编译参数。PR 集成 main 时保留 admission。这里测量软件 RegisterMap 访问，没有运行真实 QEMU 设备代码。

## 差距在哪里

先做不修改访问逻辑的 Linux 用户态 IP 采样，再做版本配对测量。负载为 8 VF、32-bit RW、identity + index、一个只做计数的全局 pre_access，无寄存器回调/日志。采样运行单独链接 `sample_ips.cpp`；正式性能数据不启用采样。

基线采到 5,825 个 IP，其中 3,485 个落在框架入口及适配器内。按函数粗分如下；内联代码落在调用者里，采样比例不是精确的独立阶段计时，不能直接换算成各操作的固定 ns。

| 位置 | 框架侧样本占比 | 包含的工作 |
|---|---:|---|
| `FormulaDecoder::fast_access` | 15.0% | 第一次 View/Hash 查找、准备分发记录和来源 AliasEntry |
| `RegisterMap::view_entry` | 15.0% | identity 后的第二次查找及目标 AliasEntry 填写 |
| `AccessResolverSlot::from_frame` | 14.3% | resolver 生命周期保护、选择适配入口和间接调用；实际用户函数样本另计 |
| `try_mmio_read_sized` | 49.0% | 内联的 mapped_scalar：identity 管理、Frame 准备、索引结果处理、权限/回调检查及存储访问等 |
| 其余包装和适配器 | 6.7% | pre_access 分发、用户 resolver 适配器、公共读入口等 |

因此，三倍差距不能归结为“一次 O(1) 查找”或“一个 hook 调用”。当前入口会把共享几何装配成 AliasEntry，再组织 Frame；identity 的目标又走一遍查找和装配。手写 switch 的转换表达式、存储位置可直接被编译器内联和合并；框架还保留运行期绑定、完整 Info、错误和生命周期语义。

汇编还显示了重复的 quotient/remainder 除法，以及 resolver shared_ptr 保留/释放周围的热点。但采样落点不等于单条指令的独立成本：对固定绑定、单 MMIO 线程的诊断二进制，仅把所选 LOCK 前缀换成 NOP、保持其余指令位置和引用计数运算不变，五轮中位数从读 125.15 ns / 写 121.77 ns 变为 120.98 / 120.37 ns。这种小幅差异不足以解释三倍，也不支持删除生命周期保护。该诊断二进制不属于补丁，不用于一般并发场景。

## 保留的实现

1. 共享 EntityLayout 的局部地址较密集时，使用连续 `PreparedAccessInfo` 数组，直接按 word 下标取条目；范围长度不得超过有效键数的两倍。稀疏或高地址空洞继续使用 Hash。表在初始化时生成，同构 View/VF 共享几何，实体指针、策略、钩子槽仍按挂载绑定。
2. 查找范围收紧到实际挂载的寄存器包络，避免父 View 的大片空洞成为无效候选。
3. finish 为满足条件的 identity 重复族建立目标 View 指针表。resolver 仍逐次执行；返回 id 后，若目标共享同一几何、没有竞争 View 或 Reserve，就复用已经查到的寄存器条目，绑定目标实例。其余情况回退完整解码。它缓存的是不变布局关系，不是 resolver 返回值。
4. 商与余数先存入局部值，再写上下文，避免写入别名导致重复读取 stride 和重复除法。

API、完整 RegAccessInfo、值复制、动态 resolver/pre_access/寄存器回调、权限、日志、事务、快照均保留。目标表在 finish 构建，之后不改变；没有新增每次 MMIO 分配。

“编译期算好表”与“编译器把 switch 优化成跳转表”不能直接画等号。表只解决定位；它不会自动内联运行期绑定的 callable 或删掉完整上下文语义。实际 Bank 实体指针也必须在实例创建时绑定。本次保留轻量布局描述，在初始化时构建有界索引，运行时同样是查表，避免逐 word consteval 展开。

固定 CPU 0，GCC 14.2、C++20、-O3、无 LTO，glibc 多线程引用计数路径。四种转换组合、无/全局 hook、读写共 16 场景，每寄存器区 10 范围。5 个配对进程批次，每次 5 passes × 8 轮，去首轮取中位数，再取进程中位数。编译与计时不并行。正确性对照检查有效 1/2/4 字节访问、存储、回调结果和 hook 次数，版本 checksum 一致。手写列取候选同进程的 range_switch 中位数。

同一候选二进制的双转换 4 场景 A/A 对照，差异分别为全局读 -2.01%、全局写 -0.11%、无 hook 读 -2.31%、无 hook 写 -3.93%。因此不把表里几个百分点的小幅变化当成稳定收益；例如 index-only + 全局 hook 的写增加 2.1%，仍需真实设备负载验证。

前置小实验中，仅替换密集 Hash 的双转换读/写约降低 7%～10%。合并 MappedAccessFrame 初始化、提前判空 logger 的另一原型没有稳定收益，已撤回。这些不同轮次的差值不能相加成独立阶段耗时。

## 编译、初始化与空间

公开头文件未在本轮改动，未重新引入逐元素模板或完整布局 consteval。`benchmarks/compile.cpp` 在相同 GCC -O2 参数下，`ELEMENTS=64` 为 4.72 秒、峰值 RSS 336,996 KiB；`ELEMENTS=16384` 为 5.51 秒、337,076 KiB。后者每实体含 10 个数组、每数组 16,384 元素、9 个实体实例，即 1,474,560 个逻辑元素；编译器处理的是声明/形状描述，没有展开这一百万个地址条目。单次进程时间只用于排除数量级失控，不能宣称几百分点的编译速度变化。

同一固定布局的共享几何表估计从 88,176 字节降至 56,032 字节；18 个 View 中，16 个 identity View 共使用 128 个目标槽、1,024 字节。统计不包括实体存储、诊断名称和所有容器开销。静态库 text/data/bss 节合计从 949,690 增至 957,504 字节（+7,814，约 0.82%）。

初始化另做五轮进程配对，每进程构建 11 次，丢弃首轮再取中位数：

| 钩子 | 改前总初始化 ms | 查表版 ms | 改前峰值 RSS KiB | 查表版 KiB |
|---|---:|---:|---:|---:|
| 无 | 5.942 | 6.356 | 12,740 | 12,520 |
| 全局 | 5.837 | 6.057 | 12,900 | 12,508 |

本组初始化总时间增加约 7.0% / 3.8%，不宣称启动加速。连续表当前先复用现有 Hash 安装/冲突处理，再转成连续存储并释放 Hash；这会有临时内存和转换工作，但不按整个稀疏地址空间分配。

`formula_scale.cpp`（512-bit 稀疏数组、8 个身份窗口）原始短循环出现不稳定的变慢结果，因此把 `N` 从 `1u << 20` 增至 `1u << 24`，以相同新源文件链接两版库，交替运行 7 轮。拉长测量后，普通写 24.57→22.68 ns、普通读 23.03→22.90 ns、identity 写 69.08→62.45 ns，没有复现短测回退；小幅普通读变化不视为收益。两版峰值 RSS 中位数均 12,160 KiB，构造约 4.07 / 4.01 ms，finish 均约 0.021 ms，checksum 一致。

## 验证与复现

0.37 同步候选严格 Release 全部 35/35 CTest；main 集成候选严格 Release 与 ASan/UBSan 各 36/36（未启用 LeakSanitizer）。新增 `formula_fastpaths` 回归以通用执行器对照，覆盖密集表空洞、收紧范围的前后边界、非二次幂 identity stride、不同高地址别名、只读入口、目标覆盖/Reserve、动态 identity/index、完整 info 复制及快照。边界断言同时检查预期实体值和 DecodeError/权限拒绝，避免仅比较两条共享解码器路径。追加边界断言后，该测试在三种构建中均再次通过。clang-format 17、文档检查、安装后独立三 TU 消费者通过。

沿用 [benchmarks/README.md](../benchmarks/README.md) 的同步版成套构建方法，四种转换组合分别编译为 `<prefix>-0-0`、`-0-1`、`-1-0`、`-1-1`：

```sh
python3 benchmarks/measure_routes.py --baseline-prefix "$RESULTS/baseline" \
  --candidate-prefix "$RESULTS/tables" --ranges 10 --blocks 5 --passes 5 \
  --out "$RESULTS/dispatch"
```

可选用户态采样（Linux x86-64，无需 perf 权限）：在相同 benchmark 对象和库的链接命令里添加 `benchmarks/sample_ips.cpp -no-pie`，然后运行：

```sh
REGFW_SAMPLE_IPS="$RESULTS/profile.ips" REGFW_BENCH_THREADS=1 \
  REGFW_BENCH_PRE_ACCESS=global REGFW_BENCH_RANGES=10 \
  taskset -c 0 "$RESULTS/profile" 120 4 1 0 mapped 0
python3 benchmarks/summarize_ips.py "$RESULTS/profile" "$RESULTS/profile.ips"
```

采样会干扰执行，仅用于定位热点；不要把它打印的 benchmark 时间当正式性能结果。采样频率受系统定时器分辨率和调度影响。
